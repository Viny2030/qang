Appendix E — Falsification register: the predictions the repository allows one to check

The book’s plan announced a full count of §1–§164 here. Chapter 28 explains why it was not done: the sections before §71 hardly use pre-registration, and many later ones leave their verdicts only in prose, worded differently. This appendix lists what can be checked with code. tools/make_appendices.py generates it with the same functions as the Chapter 28 figure (tools/make_cap28_figures.py), so its totals are the chapter’s.

E.1 Falsification statement

  • Definitions and identities are not falsified by experiments. The qg unit, the milli-qang, the probability equation and the formulas of Appendices A and B are proven or checked to machine precision in tests/. If one fails, it is a code bug, not a result.
  • Empirical claims are. Each says that a reading with qang is more accurate, cheaper or more stable than without qang, and it is fixed with a threshold before running. A failed prediction is published with its number and not rewritten.
  • What would falsify the programme as a whole. That the advantages of Chapter 29 did not repeat on real hardware with thresholds fixed in advance. Today that test has two runs on IQM Garnet (§165 and §168), with 7 of 8 predictions passed. That is too little to decide.

E.2 Verdicts stored by the code

Each file of examples/data/ with a verdict dictionary is a run whose predictions the script itself scored. The § column is the notes section that names the script.

E.3 Pre-registrations by sha256

Each examples/data/*.prereg holds the sha256 of a frozen script. The ‘before’ is checked if the hash matches the script at the commit that added the .prereg and that commit is earlier than the one of the results.

That none matches today is expected: after the run the findings are added to the script’s opening comment. In those with their own timestamp only, the .prereg and the results entered in the same commit.

E.4 Pre-registrations by commit

Each “committed … (abcdef1)” in the notes: the commit exists and in it the notes do not yet have the section.

E.5 What this register leaves out

  • The QML line (§75–§123) keeps its own count in the README: 176 predictions judged, 123 passed and 53 failed, with 4 more waiting for the IonQ hardware run (§116). It partly overlaps the tables above and must not be added to them.
  • The verdicts in prose (“Four passed; V1 failed”) of the sections that store no dictionary. They are in the notes, section by section, but counting them requires reading them one by one.
  • The sections before §71, which hardly use pre-registration: their numbers are reproducible, but they have no threshold fixed in advance.
